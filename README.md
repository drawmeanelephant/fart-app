# 💨 fart-app — Flatlophone v2

A standalone, over-the-top fart application written in [Zig](https://ziglang.org/) (v0.16.0), now with a real fart synthesizer, bundled with an adversarial RAG audit pipeline for LLM ingestion. It also ships `kujamba`: the same synth as a headless NINJAM instrument that streams fart intervals to a real server (milestone 3 of the NINJAM revival).

### kujamba mode — the butt speaks Swahili 🇰🇪

*kujamba* = to fart. Type a Swahili phrase and the butt speaks it **in fart**:
each syllable gets its own animated frame (butt + syllable cloud + emoji rain
+ screen shake) while the synthesized WAV plays through `afplay`.

```bash
zig build run -- kujamba habari yako     # or:
./zig-out/bin/fart kujamba "karibu kujamba"
```

The phrase is synthesized to `/tmp/fart_kujamba.wav`, playback starts, and the
animation is timed syllable-by-syllable to the audio (240 ms per syllable +

| `asante` | a·sa·nte (3) | **0.80 s** (confirmed by `afinfo`) |

## The Synthesizer (`src/synth.zig`)

Flatlophone v2. Pure Zig stdlib, **no libc, no file I/O**: every render is a
pure function of its input. PCM WAV, 44100 Hz, mono, 16-bit.

One fart "phoneme" (one syllable) =
**low-frequency buzzy oscillator** (pitch falls 20% across the syllable)
**+ filtered noise burst** at the attack (the *splat*) + quiet low-passed body
hiss **+ amplitude envelope** with fast attack and a ~24–34 Hz flutter wobble.

### Swahili syllable engine

Swahili is nearly pure CV. The splitter gathers consonants into an onset and
closes each syllable on a vowel. Digraphs and prenasalized consonants
(`sh ch th ny mb nd ng nj mp nt nk nz nv mv`, plus Cw/Cy like `kw`, `bw`) stay
together; a consonant that can't join the pending onset becomes its own
syllabic-nasal breath syllable (like the *m* of *mtu*); `ng'` is one consonant.

Split examples: `habari` → ha·ba·ri · `yako` → ya·ko · `asante` → a·sa·nte ·
`karibu` → ka·ri·bu · `kujamba` → ku·ja·mba · `shuzi` → shu·zi · `ng'oma` → ng'o·ma

### Vowel → base frequency

| Vowel | Base freq (Hz) |
|---|---|
| a | 92 |
| e | 110 |
| i | 138 |
| o | 86 |
| u | 74 |

### Onset class → attack / decay character

| Class | Consonants | Attack | Noise mix | Wobble | Level |
|---|---|---|---|---|---|
| stop_voiceless | p t k ch | 4 ms | 0.40 | 32 Hz, deep | 0.95 |
| stop_voiced | b d g j | 6 ms | 0.28 | 30 Hz | 1.00 |
| fricative | s sh z f v th dh h gh | 10 ms | 0.50 | 29 Hz | 0.90 |
| nasal | m n ng ny | 25 ms | 0.12 | 26 Hz, smooth | 0.85 |
| liquid/glide | l r w y | 14 ms | 0.18 | 28 Hz | 0.90 |
| none (bare vowel) | — | 8 ms | 0.25 | 28 Hz | 0.90 |

### Timing policy (syllable count sets total duration)

| Element | Duration |
|---|---|
| Syllable | 240 ms |
| Breath between syllables of one word | 40 ms |
| Breath between words | 120 ms |
| Consonant-only tail syllable (rare) | 90 ms |

Phrase duration = `n_syl × 240 + (n_syl − n_words) × 40 + (n_words − 1) × 120` ms.

### Determinism

The noise generator is seeded from a hash of the input text; every other
constant is fixed. The same phrase renders **byte-identical WAV bytes** every
call, every run (verified in-process and across separate process runs by
SHA-256). Wordless *shuzi* farts (`renderShuziWav`) are deterministic per seed.

### Tests (fail-against-silence enforced)

Every audio test asserts non-silence: replace the synthesis with silence and
**all six fail**. The suite covers WAV header validity, sample count within
1 ms of expected duration, byte-identical determinism, syllable splits on real
Swahili words (`habari`, `yako`, `asante`, `karibu`, `kujamba`, `shuzi`),
vowel-change-alters-output-bytes, and an explicit is-not-silence test.

## The NINJAM instrument (`kujamba`)

The Flatlophone as an instrument in the NINJAM room: a **headless** client — no
mic, no speaker. The synth replaces the capture device, and each interval is
uploaded to a real `ninjamsrv` as Ogg Vorbis, in time on the server's BPI grid.

```bash
zig build
./zig-out/bin/kujamba join --host 127.0.0.1:20531 --user kujamba --pass secret \
  --phrase "kujamba karibu" --seed 42 --pattern 3+1 --intervals 6
```

* **Per interval** (BPM/BPI come from the server config message): the kujamba
  phrase sequencer reads the phrase out from sample 0 of the bar and pads the
  interval tail with silence; the interval is encoded to Ogg Vorbis and
  uploaded as `0x83` begin + `0x84` chunks with a `flags=1` final, exactly
  like zclient does.
* **Rest bars** (`--pattern 3+1` = 3 fart bars + 1 rest bar) emit NINJAM
  silence markers (`0x83`, zero guid, `fourcc=0`). Dead air is never uploaded
  as audio.
* **One channel**, registered as `kujamba` via `0x82`; auto-subscribe `0x81`;
  keepalive `0xFD`.
* **Deterministic**: the upload guid and the Vorbis stream serial derive from
  `(seed, interval, channel)`, so two runs with the same seed + phrase + BPI
  produce byte-identical uploaded payload bytes. `--dump-dir DIR` writes each
  interval's payload to `interval_NNNN.ogg`; the demo compares sha256 across
  two runs.
* `kujamba check-ogg FILE --min-rms R` decodes a raw interval and fails if it
  is silent; `kujamba encode-silence FILE` is the negative-control generator.

### Offline render

The synth is useful without a room. `kujamba render` writes a phrase to a WAV or
Ogg file, shaped by the same `Fill`/`Pattern` code the session plays, so the
file is what a listener would have heard:

```bash
./zig-out/bin/kujamba render --phrase "kujamba karibu" --out karibu.wav
./zig-out/bin/kujamba render --phrase "kujamba karibu" --out bars.wav \
  --play loop --pattern 3+1 --bars 4 --bar-ms 500
./zig-out/bin/kujamba render --phrase "kujamba karibu" --out bars.ogg \
  --pattern 3+1 --bars 4 --bar-ms 500 --seed 42
```

* `--play`, `--pattern` and `--bars` shape the output exactly as they shape a
  live session; the container is picked from the `--out` extension.
* **A rest bar is exact silence, not a skipped bar.** In a session a rest bar
  uploads a silence marker rather than audio, so the room hears nothing for
  that bar and the phrase cursor does not advance. Writing silence instead of
  concatenating the play bars keeps the file's timeline identical to the live
  one and keeps `loop`/`once` phrasing in step with the room.
* With no `--bar-ms`, one bar is exactly as long as the phrase, so the default
  is "the phrase, untouched" rather than "the phrase, truncated at one second".
* Deterministic: same phrase + flags give byte-identical output. `--seed` keys
  the Ogg stream serial, not the waveform — the same split `join` has, where the
  seed keys interval ids and the synth seeds from the phrase text.

## The RAG Audit Tool (`src/audit.zig`)

A single-file, zero-dependency Zig utility that recursively traverses a source directory, semantically chunks the code, and emits an LLM-ingestible XML manifest. Designed as the ingestion layer for an adversarial RAG pipeline.

### Features

| Feature | Detail |
|---|---|
| **Sliding-window chunker** | 1024-byte windows, 150-byte overlap, snaps to `\n\n` or `\n` |
| **UTF-8 safe** | Chunk boundaries never split multi-byte characters |
| **Tokenizer-based detection** | Uses `std.zig.Tokenizer` (not naïve string search) to catch `@ptrCast`, `@ptrFromInt`, `system`, `syscall`, `extern`, `export` |
| **Function context** | Each chunk is labeled with its surrounding function name |
| **SHA-256 per chunk** | Every chunk gets a content hash for deduplication |
| **Live TUI** | Progress bar + streaming red `[WARNING]` hits printed as files scan |
| **Concurrent** | Files processed in parallel via a custom `Thread.Pool` + `WaitGroup` |
| **5 built-in tests** | Chunker edge cases, unicode boundaries, function extraction, adversarial detection |

### Run it

```bash
# Scan the src/ directory and write a manifest
zig build audit -- --src src --out manifest.txt

# Run the test suites (audit + synth)
zig build test
```
